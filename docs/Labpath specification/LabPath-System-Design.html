How to read this document

This is the engineering companion to the product spec. Product rules (P1–P8, grader classes, hidden sets, exercise-as-code) are unchanged. This document translates them into a NestJS + Prisma system the team can start building.

Stack change vs product spec §11. The product spec recommended Python/FastAPI grading workers. The team decision for this blueprint is a single NestJS codebase: HTTP API + BullMQ workers. Metrics, Assertion DSL, Slice Spec parser, and harnesses ship in TypeScript. A Python sidecar remains an optional later extraction if a metric library becomes a blocker — it is not required for Phase 0.
What must stay true from day one: hidden eval sets never reach the API database role; verdicts are three-valued (pass / fail / inconclusive); money is EUR micros; submissions and traces are durable addressable objects; users have roles learner | tutor | org_admin | admin; every exercise has at least one class A gate.

1. Purpose, constraints and stack

Phase 0 proves one thing: a graded, hidden-eval-set exercise produces feedback good enough that engineers come back. Not payments, not sandbox, not tutors.

1.1 Product constraints that bind architecture

2. System architecture

One NestJS repository, two processes: API (HTTP + SSE) and Worker (grading). They share Prisma models and a Redis queue. They do not share database roles.

2.1 Process split

API process

Accepts learner traffic. Validates submission JSON against the exercise schema. Creates Attempt / Submission / Run rows. Enqueues a job. Streams run progress. Returns scorecards with rotated failing cases only.

Worker process

Reads hidden assets from object store + harness schema. Runs harnesses under a hard budget. Writes Grade + Trace. Never serves HTTP to the public internet.

2.2 Why two database roles

Product spec §12.4: hidden eval sets never leave the server — not in API responses, traces, or error messages. The strongest enforcement is not “remember to omit the field”. It is a Postgres role that physically cannot read the table.

  • labpath_api — GRANT on schema public only.
  • labpath_worker — GRANT on public + harness + object-store IAM.
  • CI leakage test greps API fixtures for hidden-set canaries and fails the build.

3.2 Interactive exception: G1 / G2

Most exercises are “submit config → async grade”. G1 is a live mock chat. G2 is “submit a page, then watch the agent”. Those turns still go through the model gateway and write a tool-call log. Win detection stays class A: canary in output, or send_email.to equals attacker address. The grade job for G1/G2 may be short-circuited to an event detector on the same request path, with the Run still persisted.

Keep Nest module names stable. Adding Prompt Engineering (Phase 1) or Agent simulator (Phase 2) should be a new harness folder, not a new data model.

4. Grading engine on Nest

The pipeline is identical to spec §7.1. Implementation language is TypeScript.

StepWhat runs
ValidateJSON Schema for the exercise, size caps, banned constructs, E3 attempt policy, degenerate-suite guard (E1).
MaterialiseBuild retriever config, prompt, assertion suite, slice spec, or mock-app policy from payload.

4.1 TypeScript metric library (Phase 0 complete list)

RAG

recall@k, gold-span overlap, citation-id validity, nDCG@k, mean prompt tokens, model-call count

Eval

precision/recall/F1, Cohen’s κ, self-consistency, two-proportion z, BH/Bonferroni, bootstrap CI

Guardrails

canary detect, tool-log match, block rate, Wilson interval, filter token count

4.2 Assertion DSL and Slice Spec

Two separate parsers. Do not unify in Phase 0.

  • Assertion DSL — YAML, RE2 via the re2 npm package (not JS RegExp). Timeouts 50 ms / assertion, 5 s / suite, max 40 assertions, pattern ≤ 512 chars.
  • Slice Spec — hand-written boolean parser over meta.* only. Never eval(), never new Function().

5. Database design

5.1 Rules

  • UUIDs everywhere (gen_random_uuid()).
  • All money is BIGINT EUR micros. fxRate recorded on the run. No mixed-currency columns.
  • verdict is an enum of three values, never a boolean.
  • Submission payload is polymorphic JSON, validated by the exercise’s JSON Schema.
  • Hidden eval JSONL is not a Prisma model the API can query. It lives in object storage. Worker reads it with a signed URI stored in harness.exercise_assets.
  • Public sample may be copied into exercises.publicSample because the catalogue endpoint is allowed to return it.
  • Historical grades keep exerciseVersion. Never silently re-score.

5.2 Schema map

SchemaTablesWho can read
publicusers, identities, exercises, attempts, submissions, runs, grades, traces, hint_unlocks, skills, user_skill_scores, refresh_tokens, magic_linksAPI + worker
harnessexercise_assets, corpus_chunks, gen_cache, judge_cache, label_setsWorker only

5.3 Entity relationships

User 1──* Attempt 1──* Submission 1──* Run 1──1 Grade └──1 Trace (blob URI) Exercise 1──* Attempt Exercise *──* Skill (ExerciseSkill) User *──* Skill (UserSkillScore) Run.sampleSeed → makes G3 (and any sampled exercise) replayable Run.costEurMicros + fxRate → unit-economics dashboard Grade.verdict ∈ {pass, fail, inconclusive} Grade.failureClasses[] → controlled vocabulary, not free text

5.4 What is not stored in Postgres

Object store

eval_hidden.jsonl, full traces, frozen generation fixtures, RAG corpora source files, judge rubrics YAML, reference/near-miss solutions.

Git (exercise-as-code)

exercise.yaml, brief.md, hints.md, public/hidden jsonl, grader extras, solution/. GitHub Action validates and upserts metadata only.

5.5 Role model (marketplace-ready, unused until Phase 4)

learner is the only active product role in Phase 0. tutor and org_admin exist on the enum so we do not migrate user types later. No tutor tables, booking, or payouts until Phase 4.

7.5 Inconclusive (class B band / G3 Wilson)

  1. Worker returns verdict: inconclusive.
  2. UI copy: result is within measurement noise; attempt is not consumed.
  3. Worker automatically enqueues one rerun on a larger sample, same payloadHash.
  4. If still inconclusive → resolve as pass (spec §7.2).

7.6 Hints

POST /api/exercises/:slug/hints/next unlocks the next index into hint_unlocks. Hints are progressive. Tutor CTA is not shown in Phase 0. Spec allows the booking prompt only after ≥ 3 failed attempts in later phases — do not upsell on attempt one.

7.7 Trace

GET /api/runs/:id/trace returns the instrumentation blob: retrieved chunks + scores, prompts actually sent, tokens, cost, per-step latency, tool calls. Gold labels and hidden questions that were not in the rotated sample are absent. Free-tier hiding of traces is a Phase 1 concern; Phase 0 shows traces to every authenticated solver.

7. User flows — simulator-specific

7.8 RAG (R1–R4)

R1 / R2 / R4 — config form

Centre panel is structured fields (chunk size, overlap, top-k, reranker). Public sample of 5 Q/A is visible. Submit runs retrieval (R1 has zero live generations). Feedback highlights gold span vs retrieved chunks.

R3 — prompt editor (flagship)

Retrieval is fixed. Learner writes the generation prompt. Scorecard shows citation format, ID validity, gold-span overlap, refusal counts, then banded class B support. Demo this one.

7.9 Evaluation (E1–E3)

E1 YAML assertions

Editor + 10 labelled public samples. Confusion matrix on fail. Rotating 3 FP + 3 FN.

E2 judge prompt

Platform-fixed temperature 0.7, 80 items × 3. Learner does not set temperature. Malformed JSON = incorrect.

E3 slice spec

Metadata schema published in the brief. 5 submits then 24h cooldown. No candidate slice list to brute-force.

8.2 Ownership

Runs, grades, traces are readable only by the owning user (or admin). Spec §9.3: they are durable and addressable so a later share token can be added without moving blobs. Phase 0 does not implement share links.

9. Security, budgets, anti-cheat

9.1 Execution safety (Phase 0)

  • No Docker sandbox. No learner Python. No eval().
  • RE2 only for DSL patterns. Assertion timeouts as specified.
  • Slice Spec: comparison + boolean over published meta.* fields.
  • Primary live threat: prompt injection of judges via R3/E2/G3 learner text. Mitigate with quarantine delimiters, structured verdict schema, evidence binding, ~40-payload adversarial CI suite.

9.2 Budget kill

Gateway wraps every model call. Counters on the Run: tokens in/out, call count, costEurMicros. Crossing any cap in Exercise.budget sets killed_budget and stops the job. Wall-clock is a worker safety timeout, not a learner-facing gate.

Blended mean target ≤ €0.20. O8 (unit economics vs Pro price) is a Phase 1 pricing call, not a Phase 0 schema change.

9.3 Anti-cheat

  • Hidden jsonl never in public schema, never in API JSON, never in error messages.
  • Rotated failing cases: R1 = 3 of 30; R4 = 5 improved + 3 degraded; E1 = 3 FP + 3 FN; G3 = errors from the 100-item sample only.
  • sampleSeed on Run makes G3 replayable for support without publishing the pool.
  • Accept that a determined cheater beats a practice platform. Do not cripple UX.

9.4 Performance budgets

Catalogue/workspace < 1.5 s p95. Job start < 3 s. Grade < 60 s p95. Progress via SSE.
